# Contributing to Sentinel Lock

Thank you for helping improve Sentinel Lock.

## Before coding

1. Check existing issues and pull requests.
2. Discuss large architecture, privacy, or dependency changes in an issue.
3. Keep each pull request focused on one outcome.

## Pull request requirements

- explain the security or user impact;
- include tests for new behavior;
- pass the unit and compilation checks in `docs/DEVELOPMENT.md`;
- update relevant documentation;
- avoid unrelated formatting or dependency changes.

Input contents, pointer coordinates, and user activity histories must never be
logged or committed as fixtures.
